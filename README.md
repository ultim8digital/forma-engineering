# FORMA Engineering · 0.2

[![Validate FORMA](https://github.com/ultim8digital/forma-engineering/actions/workflows/ci.yml/badge.svg)](https://github.com/ultim8digital/forma-engineering/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

**Open-source CAD / CAE workbench:** parametric parts and assemblies, linear finite-element analysis, mechanism motion checks, manufacturing drawings and a choice of AI providers. [English setup guide](docs/SELF_HOSTING.md) · [Contributing](CONTRIBUTING.md) · [Security](SECURITY.md).

Личная инженерная мастерская: веб-приложение, REST API, MCP и собственный CAD-узел. Версия 0.2 добавляет численную прочность, движение шарнирных сборок, размерные чертежи и живой выбор моделей. Область применимости каждого расчёта указана в его отчёте.

## Open source

Исходники опубликованы под [MIT](LICENSE): можно использовать, изменять, распространять и разворачивать свою версию, в том числе коммерчески. Лицензии зависимостей сохраняются отдельно — см. [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Аккаунты моделей, подписки и облачные мощности в проект не входят.

Для своего запуска начни с [пошаговой инструкции](docs/SELF_HOSTING.md): она включает создание секретов, локальную базу, вход без облачного аккаунта и подключение вычислительного узла. GitHub хранит код; backend D1/R2 не работает на GitHub Pages. Публикация исходников не открывает доступ к личному сервису, проектам или вычислительному узлу автора.

## Что работает

- Интерактивный 3D-вид фактически построенной геометрии, выбор компонентов, разнесённый вид и каркас.
- Сборки до 24 компонентов, индивидуальные материал / оборудование / STEP / STL, BOM CSV, архив производства.
- Параметрическое редактирование и неизменяемые версии с происхождением результата.
- Codex CLI с локальным входом ChatGPT; Claude Code с локальным входом Anthropic; API формата chat/completions, включая локальные LM Studio / Ollama.
- Живые каталоги: Codex `model/list`, Claude SDK `supportedModels()`, совместимый сервер `GET /models`. Список обновляется с узла; модель из каталога отличается от модели с подтверждённым запросом FORMA. Успешность запросов учитывается из истории заданий, а выбор сохраняется локально в браузере.
- Прочность: CAD -> объёмная сетка Gmsh -> линейная упругость T4 -> SciPy sparse -> перемещения, von Mises, реакции, запас по заданному пределу текучести и сравнение двух сеток. Материал, источник свойств, заделка и силы задаются явно.
- Движение: вращательные, поступательные и жёсткие связи, несколько приводов, точная прямая кинематика дерева либо численное замыкание контуров. Контроль невязки/ранга и проверка B-Rep пересечений в каждом заданном положении. Есть проигрыватель, переход к столкновению и размер шага проверки.
- Чертежи: три ортогональных вида OpenCascade, габариты, диаметры и координаты цилиндрических осей, общий и индивидуальные числовые допуски. PDF A3 и DXF по деталям, сводный PDF и CSV размеров. Проверяется попадание CAD-размера в заданный интервал.
- Планировщик возвращает ограниченную JSON-спецификацию. Вывод модели не исполняется как Python. CadQuery / OpenCascade детерминированно строят геометрию в отдельном процессе с таймаутом.
- Проверки B-Rep, количества тел, заданного габарита, отсутствующих элементов и объёмных пересечений. Ошибка генерации возвращается модели, максимум три попытки.
- Облачные проекты и очередь в D1, артефакты в R2. Узел сам забирает задачи по HTTPS; входящий порт на компьютере открывать не требуется.
- Токены агентов хранятся в базе только как SHA-256. Сайт первоначально приватный. Узел использует отдельный секрет.

## Ограничения

**Прошедшая проверка не означает разрешение на изготовление.** Прочность рассчитана для отдельной детали при малых деформациях и изотропном линейном материале. Контакты и передача усилий сборки, пластичность, усталость, температура и потеря устойчивости не решаются. Пики возле заделки могут быть сингулярными. Результат без сходимости получает замечание; для FDM он всегда условный: заполнение и межслойная анизотропия не вычисляются.

Движение проверяется в дискретных положениях, максимум 61; отсутствие столкновений между ними не доказано. Замкнутая система проверяется по невязке и рангу. Динамика, трение и зубчатое зацепление не рассчитаны. Оси и центры шарниров относятся к исходной системе сборки, углы задаются в градусах, ход — в мм. Первая деталь замкнутой сборки является основанием.

Чертежи всегда имеют статус DRAFT. Автоматически размеряются габариты, цилиндрические поверхности и координаты осей относительно Xmin/Ymin/Zmin. Полнота размеров сложных карманов и профилей, GD&T, базы, технологичность, доступ инструмента и достижимость допусков требуют проверки конструктора. DXF — проекционный чертёж, не CAM: кривые аппроксимированы с отклонением 0,01 мм; для точной геометрии используй STEP. Старый `drawing.svg` остаётся общим геометрическим видом. CAM, G-code и постпроцессоров нет.

Поддерживаемые операции: box, cylinder, extrusion, fillet, chamfer. Не поддерживаемые точные элементы перечисляются в `missing_geometry`. Фотографии, произвольные STEP-импорты, вложенные сборки и редактирование поверхностей пока не реализованы. Контрольные примеры балки, каретки и четырёхзвенника созданы вручную и явно обозначены.

Первоначальная роликовая опора — **ручной учебный образец**, построенный реальным CAD-компилятором. Ось без фиксаторов; предупреждение сохранено. Это не результат генерации ИИ.

Веб-приложение адаптируется к телефону и имеет PWA-манифест. Отдельные нативные iOS/macOS приложения не собраны. Сервер предназначен для личной мастерской владельца; для публичного многопользовательского сервиса нужны tenant isolation, квоты и отдельное исполнение на пользователя. Локальные CLI запускаются только на узле владельца с доверенными запросами. OAuth-токены подписок не извлекаются и не перепродаются. CLI и API — отдельные способы доступа.

## Запуск

Требуется Node 22.13+ и Python 3.12. На этом компьютере установлен `uv`.

```sh
npm ci
npm --prefix worker-node/js ci
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r worker-node/requirements.txt
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_past_thunderbolt_ross.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_lumpy_venus.sql
npm run dev -- --port 5173
```

Для локальной разработки `.dev.vars` должен содержать `FORMA_WORKER_TOKEN`. Этот же секрет в `.env.node`. Для облака установи секрет через Sites и укажи в `.env.node` адрес опубликованного сайта. Приватный Sites дополнительно требует `FORMA_SITES_TOKEN` в заголовке `OAI-Sites-Authorization`; это поддерживаемый сервисный токен Sites, не cookie пользователя. Не меняй приватность ради доступа узла.

```sh
.venv/bin/python worker-node/runner.py --url http://localhost:5173
# Или облачный адрес из FORMA_URL в .env.node:
.venv/bin/python worker-node/runner.py
```

Для существующей локальной базы применяй только ещё не применённые миграции. Облачные миграции применяются Sites при публикации.

Для Codex: `codex login`. Для Claude: `claude auth login`. CLI должны быть установлены и авторизованы на узле. Claude Agent SDK используется только для каталога, без отправки пользовательского запроса модели. Секреты остаются в окружении узла. Каталог провайдера не гарантирует квоты или успешный запуск каждой модели; интерфейс показывает подтверждённые запросы отдельно.

## MCP для Codex / Claude / другого агента

Запусти stdio-сервер (stdout занят протоколом):

```sh
.venv/bin/python worker-node/mcp_server.py
```

Конфигурация MCP-клиента:

```json
{"mcpServers":{"forma":{"command":"/absolute/path/to/forma-engineering/.venv/bin/python","args":["/absolute/path/to/forma-engineering/worker-node/mcp_server.py"]}}}
```

Токен агента можно выпустить и отозвать в интерфейсе. Укажи его как `FORMA_AGENT_TOKEN` в `.env.node`. При отсутствии используется секрет узла. Восемь инструментов покрывают проекты, версии, схему, построение, статус, каталог моделей и инженерные отчёты. `forma_get_engineering` по умолчанию не возвращает матрицы всех кадров; для них есть `include_frames`. Агент составляет спецификацию через `forma_spec_schema` и `forma_build`, включая раздел `engineering`.

## REST API

Все запросы требуют платформенного входа либо `Authorization: Bearer <FORMA_AGENT_TOKEN>`. Запросы записи браузера дополнительно проверяют Origin. Приватная публикация Sites проверяет сервисный доступ до API.

- `GET /api/state` — проекты и узлы.
- `GET /api/models` — текущий каталог и отметки выполненных запросов; `POST /api/models/refresh` — запрос обновления каталога на узле.
- `POST /api/projects` с `{ "title": "Корпус" }`.
- `GET /api/projects/:id` — версии, спецификации и задания.
- `POST /api/projects/:id/jobs` с `{ "provider": "codex", "model": "gpt-6-astra", "prompt": "..." }`.
- Тот же маршрут с `{ "provider": "manual", "spec": { ... } }` — детерминированное построение из спецификации внешнего агента.
- `GET /api/jobs/:id` — `queued`, `running`, `complete`, `needs_review`, `failed`.
- `GET /api/artifacts/:revisionId/model.step` (также model.stl, parts.zip, bom.csv, spec.json, report.json, source.py, mesh.json, drawing.svg, engineering.json, strength-mesh.json, drawings.pdf, drawings.zip).

Без живого узла генерация возвращает 503. Отсутствующий провайдер возвращает 409. Сбой модели не заменяется ручной заготовкой. Секрет рабочего узла не выдаётся браузеру. Результаты сохраняются только после загрузки всех артефактов. Задача берётся атомарной арендой; истечение аренды отмечается как ошибка. Каждый проект допускает одну активную задачу.

## Проверка

```sh
npx tsc --noEmit
.venv/bin/python -m pytest tests/test_cad.py tests/test_engineering.py -q
.venv/bin/python tests/exercise_engineering_api.py
npm run build
```

Контрольные задачи проверяют растяжение по аналитическому решению, сходимость консольной балки, воспроизводимость сетки, баланс сил, столкновение между свободными концами траектории, замыкание четырёхзвенника, числовые допуски и состав архивов. Интеграционный тест использует настоящий CAD-узел, D1 и R2. Точные результаты записаны в `VALIDATION.md` и локальных `outputs/*-engineering.json`.

## Фоновый вычислительный узел

```sh
node scripts/compute.mjs start
node scripts/compute.mjs status
node scripts/compute.mjs stop
```

Это обычный процесс приложения, не автозапуск и не расписание. После перезагрузки Mac запускается вручную. Пока компьютер выключен или узел остановлен, сайт показывает сохранённые модели, а новое построение недоступно. Для постоянной работы перенеси узел на свой Linux/macOS сервер с Python, CadQuery и нужными CLI / API-провайдерами. CAD-процессы ограничены временем; для недоверенных публичных пользователей нужен отдельный контейнерный слой изоляции.
